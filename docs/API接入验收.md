# 云端 API 接入验收

日期：2026-10-29。当前已验证真实模型接口；GPU 微调和公网部署仍未执行。

## 配置与运行

使用用户在本机 `.env` 中填写的服务地址、密钥和模型名称。模型名称配置为 `qwen3.8-max`，响应也返回该名称；此名称是接口声明，本次没有独立核验服务商实际底层模型身份。报告应写明使用的是用户配置的兼容 API 服务，不应据此宣称是官方直连。

网页最初保留启动时的空配置，导致新填入的密钥没有立即生效。已加入“重新读取模型配置”按钮：主动从 `.env` 更新模型相关变量，不显示密钥，不改动访问口令或学习空间设置。修改配置后点击该按钮，再选择“云端 API”即可。

## 三次真实请求

| 测试 | 输入 | 结果 | 单次响应时间 |
|---|---|---|---|
| 脚本解析 | DS017：交错进出栈，学生选 A | 解释 A 可以实现，D（3 1 2）不可能，与标准解析一致 | 7.13 秒 |
| 网页提示 | DS001：顺序表按下标访问 | 给出连续存储和地址计算的方向，没有直接输出选项字母 | 3.64 秒 |
| 网页追问 | “顺序表按下标访问和按值查找有什么区别？请举一个简短例子。” | 给出直接定位与逐个比较的区别，并用 [10,20,30] 举例 | 5.75 秒 |

第一条请求的服务端 usage 字段报告输入 333 Token、输出 225 Token、合计 558 Token。其他两条请求未持久保存 usage，不推算总费用；费用以所配置服务商账单为准。这三个样例用于连通性和交互验收，不构成系统性的正确率或性能评测。

解析和追问任务会向模型提供题库标准答案与参考解析，因而这些成功样例不能描述为模型闭卷答题能力。追问中 O(n) 的按值查找描述对应顺序扫描；有序顺序表使用二分查找等算法时应另作区分。
